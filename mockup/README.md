# บ้านดี POS — interactive mockup

หน้าเว็บตัวอย่างภาษาไทย อ้างอิง `../plan/pos-mvp-spec.md`, `../plan/pos-returns-refunds-spec.md` และ `../plan/pos-purchasing-receiving-spec.md` ใช้ทดลอง flow และทบทวนหน้าจอก่อนพัฒนาระบบจริง

## เปิดใช้งาน

เปิด `index.html` ด้วย Chrome หรือ Edge ได้โดยตรง ไม่ต้องติดตั้งแพ็กเกจและไม่ใช้ CDN หรืออินเทอร์เน็ต

หากต้องการเปิดผ่าน local server จากโฟลเดอร์โปรเจกต์:

```powershell
py -m http.server 4173 --bind 127.0.0.1 --directory mockup
```

จากนั้นเปิด `http://127.0.0.1:4173` ข้อมูลตัวอย่างของ file URL กับ HTTP URL จะเก็บแยกกันตามเบราว์เซอร์

## ลอง flow หลัก

1. หน้าขายเริ่มต้นด้วยกะและตะกร้าตัวอย่าง เลือกสินค้า เปลี่ยนจำนวน หรือค้นหา SKU/บาร์โค้ด
2. กดรับชำระเงิน ใส่เงินสดหรือเลือกจำนวนแบบเร็ว ดูเงินทอน แล้วยืนยันการขาย
3. เปิดใบเสร็จ พิมพ์ซ้ำ หรือดูบิลเดิมจากประวัติการขาย
4. เจ้าของร้านยกเลิกทั้งบิลในกะเดิมที่เปิดอยู่ได้ โดยระบุเหตุผลและยืนยันคืนเงิน/สินค้า
5. เจ้าของร้านเปิดหน้า **คืนสินค้า** ค้นเลขบิล เลือกจำนวนรับคืนและแบ่งเป็นขายต่อได้/เสียหาย ระบุเหตุผล ตรวจยอดที่จะจ่าย ยืนยันจ่ายเงินสด แล้วเปิดหรือพิมพ์เอกสารคืนเดิมซ้ำได้ บิลเดิมยังอยู่และแสดงยอดคืนสะสม
6. ทดลองคืนต่างกะโดยปิดกะเดิม เปิดกะใหม่ แล้วคืนจากบิลเก่า: ยอดคืนจะหักในกะที่จ่ายเงิน กะเดิมไม่เปลี่ยน เลือกสถานการณ์ผลตอบกลับหายหรือบันทึกไม่สำเร็จได้ในแบบฟอร์มคืน
7. หน้าสินค้าเพิ่ม/แก้ราคา รับสินค้าเข้า ปรับเป็นยอดนับจริง และดู movement ได้
8. หน้า **จัดซื้อและรับสินค้า** เพิ่มซัพพลายเออร์ สร้าง PO ฉบับร่าง ออก PO แล้วรับของหลายรอบได้ ลองสั่ง 10 ชิ้น รับเข้า 6 ปฏิเสธ 1 จะค้างรับ 4 ชิ้น; รับอีก 4 ชิ้นแล้ว PO รับครบ ราคาทุนจริงที่ต่างต้องระบุเหตุผล เปิดหรือพิมพ์ PO/ใบรับเดิม และกรองรายงานตามวัน ซัพพลายเออร์ หรือสินค้าได้
9. ทดลองปิดกะก่อนรับสินค้า: PO/ใบรับยังทำได้ และไม่เปลี่ยนยอดเงินสดในกะ; ถ้าซื้อด้วยเงินจากลิ้นชัก ให้บันทึกเงินนำออกแยกเอง
10. หน้ากะบันทึกเงินนำเข้า/ออก นับเงิน ปิดกะ และเปิดกะใหม่ได้
11. คลิกชื่อผู้ใช้มุมขวาบนเพื่อสลับเจ้าของร้าน/พนักงานขาย และดูความต่างของสิทธิ์
12. หน้าระบบเลือกสถานการณ์ขายไม่ทราบผลหรือบันทึกไม่สำเร็จ สลับออฟไลน์ ส่งออกข้อมูล และเริ่มข้อมูลตัวอย่างใหม่ได้

ปุ่มลัด: **F2** ค้นสินค้า, **Enter** เพิ่ม SKU/บาร์โค้ดที่ตรง, **F8** รับชำระเงิน, **Esc** ปิดหน้าต่าง

## ขอบเขตของตัวอย่าง

### ทดลองตรวจนับสต๊อก (โมดูล 3)

1. เจ้าของเปิดเมนู **ตรวจนับสต๊อก** (`#stock-count`) ระบุชื่อ/พื้นที่และเลือกทั้งร้านหรือบาง SKU; เปิดได้หนึ่งรอบต่อครั้ง
2. สลับเป็นพนักงาน ค้นชื่อ/SKU หรือสแกนบาร์โค้ดแล้วกด Enter เพื่อเปิดกรอก **ยอดรวมที่เห็นจริง** ค่าศูนย์กรอกเป็น `0` ส่วนช่องว่างคือยังไม่ได้นับ
3. บันทึกให้ครบแล้วกด **ส่งตรวจ** ยอดนับจะถูกล็อก และสต๊อกยังไม่เปลี่ยน
4. เจ้าของตรวจส่วนต่างและเหตุผล แล้ว **อนุมัติและปรับสต๊อก** ทุกส่วนต่างต้องมีเหตุผล ถ้ายังขาดให้เปิดนับรายการนั้นใหม่เพื่อแก้พร้อมเก็บประวัติ
5. ลองขาย/รับของหลังเปิดรอบนับ: สินค้าที่มี movement จะขึ้น **ต้องนับใหม่** เจ้าของเปิดนับใหม่พร้อมเหตุผลและให้กรอกยอดจริงอีกครั้งก่อนส่งตรวจ แม้ยอดระบบกลับมาเท่าเดิมก็ยังต้องนับใหม่
6. เปิดประวัติการแก้/นับใหม่และ movement ใต้แต่ละสินค้า ดูผู้อนุมัติหรือพิมพ์ผลรอบนับได้ เอกสารที่อนุมัติแล้วแก้ไม่ได้; การยกเลิกรอบที่ยังไม่อนุมัติต้องมีเหตุผล

กรุณาใช้แท็บเดียวในการทดลอง รุ่นนี้เก็บข้อมูลในเบราว์เซอร์ ไม่มี transaction/locking ข้ามแท็บหรือเครื่อง และยังไม่มี ledger จองสินค้าของโมดูล 5

- ครบ 10 หน้า: ขาย, สินค้า/สต๊อก, ประวัติบิล, คืนสินค้า, กะ/เงินสด, รายงาน, จัดซื้อ/รับสินค้า, ตรวจนับสต๊อก, ผู้ใช้ และระบบ/backup/audit
- คำนวณเงินด้วยจำนวนเต็มหน่วยสตางค์ ไม่ให้สต๊อกติดลบ ตรวจราคาใหม่ก่อนขาย และเก็บราคาบิลเดิม
- สถานะและข้อมูลตัวอย่างเก็บใน localStorage ของเบราว์เซอร์ รายการ checkout, คืนสินค้า หรือใบรับที่ไม่ทราบผลกู้ผลเดิมได้ ข้อมูลตัวอย่างรุ่น 1–3 ย้ายเป็นรุ่น 4 โดยเก็บบิล รายการคืน และจัดซื้อเดิมไว้
- PO ไม่เพิ่มสต๊อก; ใบรับเพิ่มเฉพาะจำนวนที่รับจริง รายการรับเดิมแสดงแยกจากการรับสต๊อกด้วยมือ ยอดมูลค่ารับไม่ใช่ต้นทุนขายหรือกำไร
- การพิมพ์ใช้ browser print ไม่ตัดสต๊อกหรือเพิ่มบิลซ้ำ
- สถานะ cloud backup เป็นการจำลอง ปุ่มส่งออกสร้างไฟล์ JSON ของข้อมูลตัวอย่าง ไม่ใช่ SQLite snapshot
- การสลับบทบาทเป็นตัวอย่าง UI ไม่มีรหัสผ่านหรือ authentication จริง การกู้คืนเป็นคำอธิบายขั้นตอน
- ยังไม่ใช่ระบบขายจริง: ไม่มี Fastify, SQLite transaction, server-side authorization, cloud upload, installation/service หรือการรับรอง offline durability ตามสเปก production
- ไม่มีส่วนลด สมาชิก บัตร/QR ต้นทุน/กำไร หรือภาษีแยก การคืนสินค้านี้เป็นเพียงขั้นทดลอง UX ตามสเปกใหม่
