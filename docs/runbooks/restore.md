# Runbook: กู้คืนข้อมูลจาก backup

ใช้เมื่อฐานข้อมูลเสีย ดิสก์เสีย ย้ายเครื่อง หรือข้อมูลผิดจนต้องย้อนกลับ (R08) เป้าหมาย RTO ไม่เกิน 2 ชั่วโมงเมื่อมีเครื่องพร้อมใช้

## ก่อนเริ่ม

- หยุดการขายทั้งหมด จดยอดเงินในลิ้นชักและบิลกระดาษที่ออกหลังเวลาสำรองล่าสุด
- ยืนยันว่ามีเครื่องที่ขายอยู่เพียงเครื่องเดียว ห้ามเปิดฐานข้อมูลสำเนาสองชุดขายคู่กัน
- เตรียมไฟล์ snapshot (`pos-*.db`) **และ** manifest ชื่อเดียวกัน (`pos-*.json`) จากโฟลเดอร์ backup ในเครื่อง สำเนานอกเครื่อง หรือ cloud

## ขั้นตอน

1. หยุด server
   ```powershell
   Stop-ScheduledTask -TaskName BaandeePOS
   ```
2. เลือก snapshot ล่าสุดที่เชื่อถือได้ ดูเวลาใน manifest (`createdAt`, `counts.lastSaleAt`)
3. กู้คืน (ตั้ง `POS_DATA_DIR` ให้ตรงกับเครื่องที่ติดตั้ง)
   ```powershell
   $env:POS_DATA_DIR = "$env:ProgramData\BaandeePOS"
   npm run restore -- "D:\backup\pos-20261026T071500Z-interval-1a2b3c4d.db"
   ```
   คำสั่งจะ
   - ปฏิเสธถ้า server ยังทำงาน
   - ตรวจ checksum กับ manifest และ schema version
   - คัดลอกลงไฟล์ชั่วคราว ตรวจ `PRAGMA integrity_check` และจำนวนบิล/ยอดขาย/กะเทียบ manifest
   - ย้ายฐานข้อมูลเดิมไป `pre-restore-<เวลา>\` (ไม่ลบ)
   - ล้าง sessions ทั้งหมด บันทึก audit `system.restored`
   หากขั้นใดไม่ผ่าน ฐานข้อมูลเดิมไม่ถูกแตะ
4. เปิด server
   ```powershell
   Start-ScheduledTask -TaskName BaandeePOS
   ```
5. ล็อกอินใหม่ (ทุกคนต้องล็อกอินใหม่) แล้วตรวจ
   - หน้า **ประวัติการขาย**: บิลล่าสุดตรงกับ `counts.lastSaleAt`
   - หน้า **รายงานการขาย**: ยอดของวัน/กะ
   - หน้า **ระบบและสำรองข้อมูล**: สั่ง "สำรองข้อมูลตอนนี้" ได้สำเร็จ

## กระทบยอดหลัง restore

- บิลที่ขายหลังเวลา snapshot ไม่อยู่ในระบบ ให้เทียบกับใบเสร็จกระดาษ/ยอดเงิน แล้วบันทึกขายย้อนหลังตาม [ขายฉุกเฉิน](emergency-sales.md)
- ถ้ากะยังเปิดค้างใน snapshot ให้นับเงินแล้วปิดกะ พร้อมจดเหตุผลส่วนต่าง
- ปรับสต๊อกที่ไม่ตรงด้วย **สต๊อก → ปรับยอดนับจริง** พร้อมเหตุผล "หลัง restore"
